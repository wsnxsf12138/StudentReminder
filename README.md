# AI 学生事务助理

面向高校学生的 Windows 桌面应用项目，计划从用户明确授权的 QQ、微信会话或手动导入的消息中识别学生事务，形成可审核、可编辑、可追溯的待办、提醒和每日摘要。

首次接手项目请从 [项目接手说明](docs/项目接手说明.md) 开始。

## 下载与许可

在 [Releases](../../releases) 下载最新的 Windows x64 自包含便携包。完整解压后双击 `StudentReminder.App.exe`。新解压位置启动时使用独立试用数据目录。含模型的包可离线初筛，启用云端分析需自行配置服务商 API Key。

本项目采用 [GPL-3.0](LICENSE)。对应源码和构建说明随便携包提供。第三方组件及模型声明见 [THIRD-PARTY-NOTICES.txt](THIRD-PARTY-NOTICES.txt)。

## 当前状态

**0.6.8-alpha** 支持本地事项提醒、错过提醒补报、离线每日摘要和系统托盘。WxLocal 和 QqLocal 各自同步获授权的会话，Moect 提供微信备用导入。本地初筛后可分批调用云端。可在设置里清除微信和 QQ 直读缓存。本版修复 QqLocal 私聊会话名称，识别 QQ 公众号，缺少昵称时使用可核对的 QQ 号。 [版本交接](docs/handoffs/v0.6.8-alpha.md)

## 预期技术栈

- 桌面客户端：C#、.NET 10、WPF，面向 Windows 10/11。
- 本地存储：SQLite；密钥使用 Windows Credential Manager 或 DPAPI。
- 消息接入：WxLocal 微信直读、QqLocal QQ 直读、Moect 备用导入、手动粘贴与 JSON 导入。
- AI：由用户配置 DeepSeek 或豆包（火山方舟）的模型和 API Key。
- 提醒与摘要：Windows 本地通知、系统托盘和基于本地事件的每日摘要。

真实微信、QQ 增量入库接云 API 的验收状态见版本交接。

## 数据与配置

由用户分别开启来源同步与云端分析，应用每次启动时两者均暂停。消息库保存在本机，API Key 由当前 Windows 用户的 DPAPI 保存。提取时服务商收到脱敏正文、发送时间和时区。Git 中的测试样本为合成数据。

## 构建与运行

需要 Windows 10/11、.NET 10 SDK 和首次 NuGet 还原所需的网络。安装 SDK 可参照 [Microsoft 官方说明](https://learn.microsoft.com/en-us/dotnet/core/install/windows)。构建前关闭正在运行的应用实例，避免 Windows 锁定 DLL。在仓库根目录使用 PowerShell：

```powershell
dotnet restore StudentReminder.sln --locked-mode
dotnet build StudentReminder.sln --configuration Release --no-restore
dotnet run --project src/StudentReminder.App --configuration Release --no-build
```

点击“导入合成样本”，第一次应显示新增 117 条、重复 7 条、撤回更新 4 条；再次点击应显示新增 0 条、重复 128 条，消息总数保持 117。也可粘贴自己的授权内容，或按 [导入格式](docs/import-format.md) 导入 UTF-8 JSON。

另附 `tests/Fixtures/messages.conflicts.synthetic.json` 两条冲突证据，可用 JSON 导入验证“保留原文、标记待复核”；不计入主样本按钮的 128 条。

默认数据库和日志保存在 `%LOCALAPPDATA%\StudentReminder`，不会进入仓库。隔离测试目录的启动方式：

```powershell
dotnet run --project src/StudentReminder.App --configuration Release --no-build -- --data-dir "$env:TEMP\StudentReminder-demo"
```

启动前关闭旧版本并备份数据目录。首次启动自动升级至 SQLite schema v8。自旧 HTTP 版本升级时，迁移清除已退役本机 HTTP 来源的配置与游标，保留其已入库消息和事项证据。需要回退时，关闭应用后用升级前的备份恢复数据目录。

### 清除缓存与本地资料

- 在「设置 → 隐私与数据」点击「清除微信和 QQ 直读缓存」。确认后助理暂停采集和分析，清除当前实例的 `wxlocal`、`qqlocal` 下的解密副本、密钥、缓存游标和临时快照。已入库消息、事项、授权选择、同步进度、API Key 和旧探针保存在 `exports` 下的导出保留。再次读取会话或启动同步时会重建缓存。
- 默认缓存位于 `%LOCALAPPDATA%\StudentReminder`。本版本的 `--data-dir` 实例使用指定目录内的独立缓存。此前版本的自定义实例使用默认缓存位置，可在退出旧实例后，从默认实例的设置页统一清理。请将数据目录放在本机非同步路径。
- 旧版本曾将临时快照写到 Windows 临时目录。异常退出遗留的旧快照与独立探针目录不能可靠区分，由用户确认归属后处理。新版本的应用快照随当前实例缓存清理。清理中遇到文件占用时，关闭占用者后再次点击清理。
- 要删除整个实例的本地资料，先在主窗口核对「本地数据目录」。默认实例若启用了登录启动，先取消勾选并保存。通过托盘菜单「退出」或关闭主窗口结束程序，在任务管理器中确认对应进程已退出。先移出要保留的导出和备份，包括旧探针在缓存目录下生成的 `exports`。若目录专用于助理，可删除该目录。若目录与其他程序或文件共用，只删除助理创建的 `messages.db` 及其 `-wal`、`-shm` 文件、`logs`、`secrets` 和两种直读缓存目录（包括存在时的 `wxlocal.clearing`、`qqlocal.clearing`）。重新启动会建立空库。

## 来源配置与同步

1. 保持微信登录。在「消息来源 → 新建配置」选「WxLocal（微信直读）」，填写一个自定别名，启用实时文件监听并保存。已有配置可以直接选中。
2. 点「读取会话」，应用会在后台查找微信账号目录并列出会话。勾选有权处理的会话，点「保存会话选择并暂停」，再点「开始后台同步」。可先用「同步一次」核对新增数量。WAL 文件变化会触发增量同步，轮询作为兜底。 [WxLocal 接入说明](docs/wx-local-reader.md)
3. QQ 直读同理：保持 QQ 登录，选「QqLocal（QQ直读）」填写别名并保存，读取会话并勾选后开始同步。 [QQ 接入说明](docs/qq-local-reader.md)

「Moect 备用导入」可扫描已导出的授权群 JSON。Moect 界面负责刷新快照和导出文件。 [备用导入步骤](docs/moect-watch.md)

`QQMessageTest` 可独立运行，连接本机已启用的 NapCat OneBot 正向 WebSocket。第一阶段用它验证已指定群聊和好友私聊的实时文字事件。 [QQ 环境验证](docs/poc-napcat.md)

保存配置或会话选择会暂停同步。「同步一次」完成后自动暂停。「开始后台同步」持续运行，同一时刻可各启用一个微信来源和一个 QQ 来源。兜底轮询间隔可设为 60～300 秒，首次回溯默认 7 天。QQ 撤回帧无法可靠关联时显示需复核。

## AI 分析与事项审核

1. 打开「AI 分析 → 模型设置」，选 DeepSeek 或豆包，输入 API Key 或沿用已保存的密钥。可点「获取模型列表」，搜索并选择模型，也可手填 ID（豆包可填火山方舟接入点 ID）。「测试连接」只提交一条固定合成文本。
2. 在「本地直读自动分析」再次勾选要分析的会话，点击「开启自动分析」。仅处理开启后发送且经本地直读（微信/QQ）新入库的相关文字。最小化窗口可以继续分析。暂停、关闭分析窗口或更改来源设置时，会取消并等待在途任务结束。
3. 若需补分析历史消息，先暂停自动分析，再在「历史消息」选择会话和日期范围。预览脱敏内容并勾选要提交的消息。已被轻筛跳过的消息也可手动选择。Moect 导入和手动粘贴的内容可走此入口。
4. 打开「事项 → 待确认」，查看证据并按需改字段。变更、取消或疑似重复可先查看已有事项再选择关联。确认后在「已确认事项」查看版本、标记完成或删除。已确认事项可离线操作。

逐条模式的主消息至多 2,000 字符，输出上限 800 Token。每日本地时间最多 100 次提取请求（含重试），间隔至少 10 秒。分析面板显示请求数、Token 用量及失败。缺少明确时刻时，审核表保留原文供补录。

### 本地初筛与联合分析

- 在「AI 分析 → 本地初筛」测试 Qwen3.5 2B 或 4B 的 GGUF，勾选并保存。程序在本机用随包提供的 LLamaSharp CPU 运行时推理。将 `Qwen_Qwen3.5-2B-Q4_K_M.gguf` 放在 EXE 同级的 `Models` 目录可自动识别，也可从界面选择本地文件。
- 混合模式按会话分别排队，默认累计 4 条主消息或最早一条等待 120 秒时提交一批，计为 1 次云端请求。「本地初筛」可设置每批 1～4 条、最长等待 1～900 秒，暂停或退出后的未提交消息可在历史中手动分析。
- 每条主消息最多附带 3 条同一授权会话内的启用后前文。云端接收脱敏片段、各自发送时间、时区和临时发言代号。本地运行失败会暂停分析。
- 支持仅供知悉的校园通知，以及含操作、提交对象或办理路径的问卷和表单通知。讲座预约时间和讲座开始时间可分别审核。若链接在脱敏时被隐藏，可查看本地来源证据。
- 历史消息可手动勾选同一会话的 2～4 条并点击「联合分析」，预览后确认发送。至少一条需可提取；其余可为已经分析的上下文。仅知道日期的事项可以填入日期，补录具体时刻后才安排定时提醒。

## 今日、提醒与托盘

1. 在「事项」确认含明确开始或截止时间的候选。开始和截止默认提前 1 天、2 小时提醒。打开「设置」可为两类时间分别设置提前分钟数，留空关闭对应类别。
2. 「今日」展示离线每日摘要，默认 07:30 生成，也可手动刷新。点「查看详情」可回到事项或候选的来源证据。「错过的提醒」显示原定时间、送达不明和提交失败记录。
3. 「AI 润色」使用已保存的 DeepSeek 或豆包配置，确认预览后提交脱敏的已确认事项字段。每日定时摘要在本机生成。
4. 最小化进入托盘，关闭主窗口默认退出。「设置」可启用关闭后驻留，或在使用默认数据目录时启用登录 Windows 后启动。托盘菜单提供「打开今日」「暂停采集」「退出」。
