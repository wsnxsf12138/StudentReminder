# ADR-001：首轮开发使用手动导入

- 日期：2026-11-10
- 状态：仅首轮开发决策；真实数据源选型未定。
- 对应任务：P1-01～P1-05；用户已明确选择计划书第 12.3 节的推荐首轮开发包。

## 决策

本轮使用手动粘贴、统一协议 JSON 和合成样本，验证本地消息导入、幂等存储与证据展示。不连接 QQ、微信及第三方采集程序，不调用云端 AI。

计划书中 P1-01 对 P0-05 的依赖，本轮只在“无真实采集器”的前提下暂缓：领域接口保留可替换能力，不预先绑定微信主适配器。该决策不代表 P0-02～P0-05 已完成，也不允许据此启用真实采集。

## 后续进入条件

进入 P2 前，须完成 P0 的依赖版本及许可复核、获得必要授权、在隔离测试条件下完成当前机器的接口验证，并更新本 ADR 记录真实微信主备选型、QQ 可用条件和降级策略。WeFlow、WeMemory、qqflow-server 当前均未在本项目验证。

## 2026-11-11 更新

微信的自动同步候选采用 WeFlow Rust CLI API v2 轮询。发布版已通过合成加密库的游标和重启补拉测试。Moect 作为可用的离线降级，已用真实单群验证导出、导入和去重。WeMemory 保留轮询适配器，当前因授权 403 暂停真实验证。切换同步适配器通过来源面板完成，先暂停旧来源。Rust 账号变更时为新账号新建别名。

QQ 使用 qqflow-server。监听已就绪，数据库处于未注册状态。微信和 QQ 的真实增量选型仍须本机授权后验收。 [第二阶段验收](p2-verification.md)

## Moect 定时导入

用户选择 Moect 单群导出作为当前微信接入路径。助理默认每 30 分钟处理导出目录中的新文件，间隔由用户设置。新入库文字进入待分析队列，可用用户配置的 DeepSeek 或豆包 API 生成候选事项。Moect 快照刷新及生成 JSON 仍由其界面触发。 [定时导入配置](moect-watch.md)
