# 0.6.7-alpha 版本交接

## 版本定位与目标

- 完成日期：2026-11-13。公开源码快照由发行标签 `v0.6.7-alpha` 定位。SQLite 仍为 schema **v8**。
- 任务 ID：ISSUE-01，承接 `0.6.6-alpha` 交接「已知问题与下一步」第 1 条。
- 本轮范围：修复 QqLocal 群聊消息中少数发送者无法解析为昵称、显示为 `u_` 开头 uid 或纯数字群号的问题。
- 实际完成：`40020` 被 QQ NT 误填为群号的群系统消息显示「系统」；真实 uid 但既非好友、也不在 `group_member3` 的发送者用消息行内 `40093` 昵称快照兜底。
- 未完成：本轮不涉及另外三项遗留事项——`direction` 语义复核、中间版本补标签、EXE 签名与干净机验收。

## 使用与复现

- Windows 10/11、.NET 10 SDK（以 [global.json](../../global.json) 为准）。运行 `dotnet restore StudentReminder.sln --locked-mode` 与 `dotnet test StudentReminder.sln -c Release --no-restore`；构建前先关闭占用输出目录的应用实例。
- 用户操作不变：保持 QQ 登录，进入「消息来源 → QqLocal」点「读取会话」。此前显示为数字群号的群系统消息（成员变更、群公告等）改显示「系统」；此前显示 `u_` uid 的退群或未缓存成员，在消息带昵称快照时显示昵称。
- 仍可能看到 `u_` uid 的情形：该成员既不在好友库、也不在 `group_member3`，且消息行 `40093` 为空。属数据源覆盖缺口，界面回退 uid 是有意行为。

## 数据与兼容

- 数据目录、日志与直读缓存边界不变；本版未新增缓存文件。
- schema v8，无迁移、无字段变更。修复只在读取层：`src/StudentReminder.QqLocal/QqMessageReader.cs`。
- `ReadMessages` / `ReadMessagesAfter` 在消息表存在 `40093` 列时额外读取该列并把值交给 `ResolveSender` 作最终兜底；消息表缺少该列（旧 QQ NT 版本）时按原语句读取，不报错、不丢消息。
- 显示优先级保持不变：本人「我」→ 群系统消息「系统」→ `group_member3` 群名片 > 昵称 > 备注 → 好友备注 > 昵称 → `40093` 快照 → uid / QQ 号。
- 回退：退出旧实例后可回退到同为 schema v8 的 `0.6.6-alpha`，无需数据迁移。

- 新增合成测试：

## 已知问题与下一步

- `40093` 覆盖率有限（群消息收到方向约 41.5%，私聊几乎为空），因此只作兜底；映射表未命中的极少数成员仍显示 uid。
- `40093` 语义（发送时刻昵称快照）基于当前 QQ NT 版本归纳，QQ 升级后需复核该字段含义与覆盖率。
- 遗留待办（本轮未动）：`direction`（`40013`）语义复核、中间版本补标签、EXE 签名与干净机验收。
