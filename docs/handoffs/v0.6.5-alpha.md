# 0.6.5-alpha 版本交接

## 版本定位与目标

- 完成日期：2026-11-13。公开源码快照由发行标签 `v0.6.5-alpha` 定位。
- 本轮范围：修复 QqLocal 消息发送者名称显示为 QQ 号的问题，并补齐缺失的 `0.6.3-alpha` 交接文档。
- 实际完成：消息发送者按 uid 解析为好友备注/昵称或群成员群名片；「我发出的」与系统消息被正确区分。
- 未完成：群成员若既非好友、又不在 `group_member3` 表，发送者仍回退显示 uid；这是数据源覆盖范围的限制。

## 使用与复现

- Windows 10/11、.NET 10 SDK。运行 `dotnet restore StudentReminder.sln --locked-mode` 与 `dotnet test StudentReminder.sln -c Release --no-restore`。
- 用户操作与以往一致：保持 QQ 登录，进入「消息来源 → QqLocal」读取会话并同步。消息发送者一列即显示好友备注/昵称或群成员群名片，本人消息显示「我」，系统通知显示「系统」。

## 数据与兼容

- SQLite 继续使用 schema v8，无迁移、无字段变更。
- 新增读取 `group_info.db` 的 `group_member3` 表：`60001`（群号）、`1000`（成员 uid）、`64003`（群名片）、`20002`（昵称）、`64029`（备注），显示优先级为群名片 > 昵称 > 备注。读取为只读快照，不产生写入。
- `BuildMessage` 的 `direction` 判定修正：`0` 为收到、`3` 为系统通知、`1/2/4/5` 为我发出。`SenderId` 仍以 QQ 号优先（用于去重与哈希），仅 `SenderName` 显示逻辑调整。升级前退出旧实例，回退到 schema v8 的旧版本无需迁移。

## 验收证据

- 本机 `dotnet test StudentReminder.sln -c Release --no-restore` 通过，Release 构建 0 警告、0 错误，159 项测试全部通过。
- 新增 `Reader_ResolvesSenderNamesFromBuddyAndGroupMemberTables` 回归测试：群名片优先于好友备注、`direction=2` 识别为「我」、sender 为空的系统消息显示「系统」、私聊 sender 使用好友备注。
- 用本机解密库核对 `direction`（`40013`）取值分布：`0`（收到）、`3`（系统，sender 为空）、`1/2/4/5`（我发出）；`group_member3` 表含群名片、昵称、备注三列，与修复逻辑一致。

## 已知问题与下一步

- 群成员若非好友且不在 `group_member3`，发送者回退显示 uid（`u_` 开头），属数据源覆盖限制，暂不处理。
- `direction` 语义基于本机 QQ NT 版本归纳（`1/2/4/5` 为我发出），QQ 更新后若新增取值需复核。
