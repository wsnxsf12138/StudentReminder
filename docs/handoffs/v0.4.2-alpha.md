# 0.4.2-alpha 版本交接

## 版本定位与目标

- 完成日期为 2026-11-12。用 `git rev-parse v0.4.2-alpha^{commit}` 定位验收提交。
- 范围为 QQ NT 本地直读接入：新增 `StudentReminder.QqLocal.Adapter`，实现 `QqLocalSourceAdapter` 接入 `SyncCoordinator`，并把 AI 自动分析从微信泛化到「本地直读」（微信 + QQ）。承接 v0.3.0 微信直读的同构思路，复用 `StudentReminder.QqLocal` 读取模块（合成测试 140/140、本机真实验证通过）。
- 适配器、账号绑定、消息映射与 AI 分析范围均通过合成验收。真实 QQ 账号实时入库与云 API 分析待验收。

## 使用与复现

- Windows 10/11、.NET 10、WPF。验收使用 .NET SDK 10（`global.json` 固定 10.0.100）。
- 运行 `./scripts/Test-Project.ps1` 检查，或 `dotnet build StudentReminder.sln --configuration Release` 后 `dotnet run --project src/StudentReminder.App --configuration Release --no-build` 启动。
- QQ 保持登录（QQ NT 只会把已登录账号的密钥载入进程内存）。在「消息来源」新建配置选「QqLocal（QQ直读）」，填写自定别名、启用实时文件监听并保存；点「读取会话」，勾选授权会话，再「保存会话选择并暂停」及「开始后台同步」。可先「同步一次」核对。 [操作步骤](../../README.md#来源配置与同步)
- AI 分析：「AI 分析 → 本地直读自动分析」勾选微信或 QQ 会话即可开启自动分析。

## 数据与兼容

- 默认数据目录 `%LOCALAPPDATA%\StudentReminder`。SQLite schema 由 v5 升级到 v6：`source_configs` 允许 `qqlocal`（端口 0），新增「同一时刻只允许一个 QQ 来源采集」约束；不改变既有表结构语义，升级自动完成。
- QQ 解密缓存 `%LOCALAPPDATA%\StudentReminder\qqlocal\<qq>`（含明文库 + keys.json + wal-cursor.json）视同聊天明文，不进同步盘，纳入一键清除范围。
- 回退时关闭应用并换回 0.4.1-alpha。升级或回退前建议备份数据目录。

## 已知问题与下一步

- 账号发现按本地数据库最近写入时间选择目录；多账号时先暂停、再用新别名创建来源。密钥提取依赖 QQ NT 内存布局（`x'<key><salt>'` 字面量、1024 头 / 48 保留区），QQ 升级后若提钥失败需更新 `QqConstants`/`QqKeyExtractor`。
- 下一步在真实 QQ 中选一个授权测试会话，先「同步一次」核对入库，再启用后台同步与自动分析。 [QQ 接入说明](../qq-local-reader.md)
