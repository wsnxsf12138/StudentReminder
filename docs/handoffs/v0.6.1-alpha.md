## 版本定位与目标

- 完成日期为 2026-11-13。代码验收提交为 `464d5c8`，完整快照由本地标签 `v0.6.1-alpha` 定位。
- 延续 P3-02、P3-03、P3-04、P3-06。本轮实现本地初筛后的定量、定时批提取，补充校园公告、重要通知、问卷、表单和材料办理、讲座预约及日期解析。P5 安装包仍待交付。

## 使用与复现

- 环境为 Windows 10/11、.NET 10 Desktop Runtime。本机试用入口为 `artifacts/v0.6.1-alpha/StudentReminder.App.exe`，包含 Qwen3.5 2B Q4_K_M 权重和 LLamaSharp CPU 后端。源码构建及验证运行 `./scripts/Test-Project.ps1`。
- 打开「AI 分析 → 本地初筛」，勾选启用，可设置每批 1～4 条主消息及最长等待 1～900 秒，默认 4 条或 120 秒。保存后，在「本地直读自动分析」选择已经授权的会话并开启。每个会话分别排队。达到条数或最早入队消息等到上限时，可提交一批。云端可用性、请求间隔及每日预算可能延后提交。
- 在「事项 → 待确认」核对动作、提交对象、办理路径、日期和来源证据。讲座预约开放及截止归入「报名／预约」，讲座本身归入「活动」。只有「中午前」等模糊时段时会保留日期及原文，可手动补录时刻。问卷链接若在脱敏时被隐藏，可从本地来源证据查看。
- 使用独立目录启动时可执行 `dotnet run --project src/StudentReminder.App -c Release --no-build -- --data-dir "$env:TEMP\StudentReminder-batch-demo"`。

## 数据与兼容

- 默认数据目录为 `%LOCALAPPDATA%\StudentReminder`。真实消息、证据、配置、日志及 DPAPI 密钥均留在本机目录。自动分析仍须手动开启。每批只含同一授权会话中启用后新入库的主消息及每条关联前文的脱敏片段，携带原发送时间、时区和临时发言代号。提交前重新校验授权及证据。
- SQLite 继续使用 schema v8。批次设置存入原有 `app_settings`，此前未保存的设置用默认值。每个批次共用一条 `ai_requests` 记录，各消息独立保存状态和候选证据。
- 回退前退出应用并备份整个数据目录。回退到同为 schema v8 的 v0.6.0-alpha 时可使用备份副本，旧版忽略批次设置。回退到使用 v7 的版本需恢复升级前的 v7 数据目录。
