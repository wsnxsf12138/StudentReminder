- 日期：2026-11-10；状态：协议与合成验收版完成，三个候选程序的文件安装完成；真实采集尚未验收。
- 版本标签：`v0.2.0-alpha`，定位代码、安装脚本/清单与交接的完整快照。
- 应用代码验收提交：`114511cec11390d3ff724d6a879c6d16811504bb`；版本标签另外包含最终安装清单和交接文档。

- 本轮：P1-06、P2 协议代码及合成验证；用户追加项目内安装 WeFlow、WeMemory、qqflow-server。未授权自动读取真实聊天，本轮未配置真实账号与数据库凭据。

## 使用与复现

- Windows 10/11、.NET SDK 10.0.403；核心项目使用锁定 NuGet 依赖。WeFlow 构建另需 Node 24 / npm。
- `./scripts/Test-Project.ps1`：锁定还原、Release build、全套测试。
- `dotnet run --project src/StudentReminder.App --configuration Release --no-build`：桌面端。
- 合成服务：`dotnet run --project tools/StudentReminder.ContractHost --configuration Release --no-build -- --port 19031 --provider weflow`；测试 Token 为公开的 `synthetic-contract-token`。
- 来源页面保存配置→检查连接→读取会话→选择并保存→单次或后台同步。每次启动暂停；配置/会话变更先停在途请求。单个来源仅处理保存的选择，一个时刻只允许一个微信采集器。

## 数据与兼容

- 默认 `%LOCALAPPDATA%\StudentReminder`；演示使用独立 `artifacts/p2-demo`，不接触默认数据。Token 存于 `secrets/*.dpapi`，只对当前 Windows 用户解密，不入 SQLite 和日志。
- schema v2 使用新增 002 迁移；001 原文未改。v1 证据保留，旧 0.1 应用会拒绝较新数据库。
- 回退前关闭应用并备份完整数据目录；回到 v0.1 时使用备份的 v1 数据库或独立目录，不能把 v2 库直接交给旧版。
- `IDataSourceAdapter` 增加 IDisposable，SubscribeAsync 改为 SourceNotification；前一版无外部插件消费者。
- 默认仅轮询选中会话；全局 SSE 需额外明确授权，因为其在内存中接收上游所有会话片段。QQ 撤回不能可靠关联时提示复核，不随意修改原文。

## 已知问题与下一步

- 真实微信 / QQ 授权、数据库就绪、接口兼容、WeMemory 组合游标及长期稳定性未验证；完整 M2 的真实采集门槛未通过。
- QQ 撤回 ID 语义不一致仍需真实 PoC；全局 SSE 在应用离线时的撤回覆盖不能保证。
- 第三方程序的文件部署、基础版本检查不等于已接入账号。微信两候选不要同时启用采集，切换真实账号要换本地别名。
- 当前固定的 WeFlow 源码要求外部 WCDB 实现：`wcdbCore.ts` 只使用设置中的库路径或 `WCDB_DLL_PATH`，不内置此实现；本轮未配置，因此便携客户端部署后仍不能直接读取微信数据库。
- QQ 临时启动健康检查命令被自动审批拒绝（工具仅返回 blocked by policy），该运行检查未执行；已验证官方包、EXE 哈希和 `--version`。WeMemory 未打开 GUI 或配置数据库/授权；其程序无 Authenticode 签名。
- P3 AI / 事件、P4 提醒 / 摘要均未实现。后续先由用户确定真实授权测试账号和会话，再执行 P0 PoC 与是否正式进入真实同步的决策。
