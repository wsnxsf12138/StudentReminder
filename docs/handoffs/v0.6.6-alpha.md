# 0.6.6-alpha 版本交接

## 版本定位与目标

- 完成日期：2026-11-13。公开源码快照由发行标签 `v0.6.6-alpha` 定位。
- 本轮范围：修复 QqLocal 会话列表仍可能出现名为「0」的伪群聊的问题。
- 实际完成：读取会话时过滤 peer 为 `0` / 空的占位会话；重新读取会话时清理早前版本已持久化的「0」占位会话记录。
- 未完成：无新增已知问题，见「已知问题与下一步」。

## 使用与复现

- Windows 10/11、.NET 10 SDK。运行 `dotnet restore StudentReminder.sln --locked-mode` 与 `dotnet test StudentReminder.sln -c Release --no-restore`。
- 用户操作：保持 QQ 登录，进入「消息来源 → QqLocal」点「读取会话」。会话列表不再出现名为「0」的伪群聊；此前已持久化的「0」占位会话随本次读取被清理。

## 数据与兼容

- SQLite 继续使用 schema v8，无迁移、无字段变更。
- `0.6.4-alpha` 已过滤 QQ NT 群消息表（`group_msg_table`）中 peer 为 `0` 的占位行，避免新发现「0」会话；本版补充对早前版本已写入 `conversations` 表的 `external_id` 为 `0` 或空的占位会话的清理：`MergeConversationsAsync` 在重新读取会话时删除该类占位记录，`ReadConversationsAsync` 读取时一并过滤。
- 「0」占位会话从未被选择，不产生已入库消息；清理仅删除会话记录，不影响其他数据。升级前退出旧实例，回退到同为 schema v8 的旧版本无需迁移。

## 验收证据

- 本机 `dotnet test StudentReminder.sln -c Release --no-restore` 通过，Release 构建 0 警告、0 错误，160 项测试全部通过。
- 新增 `ReadAndMergeDropBogusZeroPlaceholderConversation` 回归测试：向 `conversations` 表直插一条 `external_id='0'` 的占位会话，验证读取时被隐藏，重新合并会话后被删除。
- 用本机应用库核对：`conversations` 表存在一条 `external_id='0'`、`name='0'`、`type='group'` 的历史占位记录，关联消息 0 条，与本版清理逻辑一致。
