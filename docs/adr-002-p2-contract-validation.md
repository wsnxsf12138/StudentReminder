# ADR-002：第二阶段先做协议验收，再安装本机候选服务

- 日期：2026-11-10
- 状态：按用户明确选择执行；不代表真实账号接入已验收。
- 范围：P1-06、P2 的适配器与同步基础、合成服务验收，以及用户追加的项目内安装。

## 决策

微信工程主适配器暂用 WeFlow，WeMemory 保留为轮询备选；QQ 使用 qqflow-server。选择依据是公开协议的可实现性与可替换接口，真实主备选择仍须 P0 的当前机器实测。

在没有真实账号与数据库访问凭据时，先用独立的 loopback 合成服务验证鉴权、字段映射、分页、重连、授权会话过滤和事务检查点。随后从官方来源将候选程序部署到项目目录，源码与安装状态纳入项目管理。此授权补充 ADR-001 的开发顺序，不免除真实采集前的授权和兼容性检查。

## 边界与兼容

- 默认只轮询用户选择的会话；每次应用启动暂停采集，须手动恢复。
- WeFlow 与 QQ 的原生 SSE 为全局通道，可能包含未选择会话的正文片段。只有用户明确勾选说明后的全局推送选项才订阅；本地仅保存已选择会话。WeMemory 不启用 SSE。
- SSE 为提示通道，成功连接、重连和周期轮询均走拉取补齐；分页内容与游标同事务提交，关闭来源或改变选择后，旧配置请求不能继续提交。
- WeFlow 撤回只按可靠消息 ID 标记并保留原证据。QQ 原生事件中的 rawid 与 Pull 消息 ID 存在不同语义，当前提示需复核，不猜测关联；该差异须真实 PoC 进一步验证。
- `IDataSourceAdapter.SubscribeAsync` 从消息对象改为通知对象，并增加 `IDisposable`；这是 0.1→0.2 的接口变更，无已发布外部插件兼容承诺。
- SQLite 从 v1 升级到 v2，保留已发布的 001 迁移，新增来源配置、版本检查及撤回标记。应用版本和 schema 版本独立。

## 尚不成立的结论

合成验证、文件部署、程序版本检查都不等于真实微信/QQ可采集。P0 的真实数据库授权、客户端版本兼容、授权状态、账号切换和长时间运行尚需测试；本版本不作这些承诺，也不实现密钥提取或自动注册数据库。
